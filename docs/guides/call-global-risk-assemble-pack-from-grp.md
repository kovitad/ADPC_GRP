# Call Global Risk `assemble_pack` from GRP

**Audience:** GRP and Global Risk developers  
**Purpose:** reproduce the Phaya Thai flood-exposure lookup and locate the implementation in source.

## What produced the result

The lines below are the trace returned by Global Risk's `assemble_pack` tool:

```text
aoi[Phaya Thai District] 9 km2 via admin boundary ~9 km²
clip[hazard_flood]
retrieve[forecast] ... -> 0 hits
retrieve[retrospective] ... -> 3 hits
documents[3] cited
exposure[hospitals] 9/12
exposure[schools] 8/8
exposure[buildings] 9945/10328
exposure[roads] 305.4km
risk_l2[hazard_flood] ...
```

Those AOI, retrieval, exposure and Layer-2 risk lines are generated by the upstream Global Risk
platform, not calculated by the GRP web request. GRP validates the returned area, optionally adds
its own exact-area citations, asks its configured language model to word a brief from the bounded
evidence and displays a separate GRP trace.

This line is important:

```text
GRP · Reused Global Risk evidence: e01f07cf8b51cfac assembled 2026-10-06T06:27:52.305239+00:00
```

It means that particular question did **not** make a fresh `assemble_pack` call. GRP reused the
person's stored evidence pack for the same place. Set `refresh=true`, or use **Gather again from
Global Risk** in Planning, to force one new call.

## Direct MCP tool call

A Global Risk MCP client can call the tool directly with:

```json
{
  "tool": "assemble_pack",
  "arguments": {
    "pack": "risk",
    "place": "PHAYA THAI District, BANGKOK, Thailand",
    "hazard": "flood",
    "focus": "Check flood exposure for schools, hospitals and roads in Phaya Thai District, Bangkok, Thailand."
  }
}
```

The exact MCP envelope is supplied by the MCP client library. Do not put a SERVIR access token in
the arguments, logs, documentation or source code. GRP obtains the signed-in person's short-lived
token from its server-side session and gives it to the MCP transport.

## Call through the GRP API

GRP uses a background lookup because a real district `assemble_pack` can take longer than a normal
web request.

Start the lookup:

```http
POST /api/v1/planning/lookups
Content-Type: application/json
Cookie: <signed-in GRP session>
X-CSRF-Token: <value of the grp_csrf cookie>
```

```json
{
  "message": "Check flood exposure for schools, hospitals and roads in Phaya Thai District, Bangkok, Thailand.",
  "place": "PHAYA THAI District, BANGKOK, Thailand",
  "hub_code": "adpc",
  "refresh": true,
  "history": [],
  "layers": []
}
```

A successful start returns a job rather than the answer:

```json
{
  "job_id": "<job-id>",
  "state": "running",
  "poll": "/api/v1/planning/lookups/<job-id>"
}
```

Poll with the same signed-in session:

```http
GET /api/v1/planning/lookups/<job-id>
```

Continue until `state` is `succeeded` or `failed`. The browser currently polls every two seconds
and keeps tracking the job for up to ten minutes. Do not automatically submit a second job merely
because the first request is slow.

### Browser-console example

The application's `GRP.request` helper automatically adds the CSRF header. From a signed-in GRP
page, a developer can run:

```javascript
const started = await GRP.request("/api/v1/planning/lookups", {
  method: "POST",
  body: {
    message: "Check flood exposure for schools, hospitals and roads in Phaya Thai District, Bangkok, Thailand.",
    place: "PHAYA THAI District, BANGKOK, Thailand",
    hub_code: "adpc",
    refresh: true,
    history: [],
    layers: [],
  },
});
console.log(started);
```

Use the returned `poll` URL with `GRP.request(started.poll)` until the job finishes.

## What GRP sends to MCP

The core call is:

```python
pack_result = await mcp.call_tool(
    "assemble_pack",
    {
        "pack": "risk",
        "place": place,
        "hazard": "flood",
        "focus": payload.message
        + (f" Layers chosen: {', '.join(layers)}." if layers else ""),
    },
)
```

GRP then:

1. refuses an error or non-OK tool result;
2. stores a successful pack for bounded reuse;
3. verifies that the returned AOI is the requested district;
4. screens unsupported evidence for the MVP contract;
5. attaches exact-area GRP citations when available;
6. asks the configured model to word only the supplied citations and declared gaps; and
7. returns the evidence and the separate GRP execution trace.

`GRP · Added GRP figures: 0 GRP citation(s)` means no matching local citation was attached for that
answer. It does not remove or change the Global Risk exposure values.
